## Evidence standards

For each project, record the objective, scope and authorization, environment, methods, observations, severity rationale (where applicable), remediation, validation, and lessons learned. Keep evidence reproducible and redact identifying information.

Only test systems you own or have explicit permission to assess. Use isolated labs and synthetic or sanitized data. Never publish passwords, API keys, personal data, private data, sensitive logs, or details that expose live targets.

## Suggested project sequence

1. Complete a network security assessment in a private lab.
2. Audit a deliberately vulnerable local application and document fixes.
3. Harden a Django sample application and validate the changes.
4. Build a small SOC lab and document a detection with synthetic events.
5. Run a tabletop incident-response exercise and record a sanitized timeline.
6. Create a phishing-analysis exercise using a harmless sample message.
7. Maintain a risk register and a concise security policy.
